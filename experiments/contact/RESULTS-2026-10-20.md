## Cold-provider failure and correction

The first pilot was stopped after provider initialization failures. Delivered
base answers could still make the upstream task summary say `ok`; those records
are not qualified optimization results. The experiment driver now stops on a
fallback stage and cannot freeze an artifact from such a campaign.

The diagnostic exposed a missing `zod/v4` peer in an automatically resolved SDK
cache, while the guest also had Node 18 below the SDK's declared requirement.
The provider is now installed explicitly as `@ai-sdk/deepseek@3.0.69` with
`zod@4.3.6`, imported through its installed entrypoint, and tested with Node 24.
Its lockfile hash is recorded in the campaign identity. The failed run is kept
separately from the subsequent pilot.

## Budget evidence

The single host gateway covered both pilots and canaries. The guest held only a
temporary gateway token, not the upstream API key. Every accepted completion
request was reserved before forwarding; refused requests were not forwarded.

| Measurement | Value |
| --- | ---: |
| Approved ceiling | 5 USD |
| Conservative reservations retained | 4.992418 USD |
| Forwarded completion requests | 163 |
| Observed input tokens | 1,514,793 |
| Observed output tokens | 25,346 |
| Forwarded requests missing usage | 0 |
| Usage-priced estimate at published peak cache-miss rates | 0.484853 USD |

Reservations use request-byte bounds and twice the published Flash peak token
rates; they are not released when actual usage is lower. Consequently the
reservation ceiling can stop a pilot well before its usage-priced estimate
reaches 5 USD. The estimate is not an invoice or a verified account debit.
The partial run also logged a client disconnect (`BrokenPipeError`); reservations
were retained and the stop was not treated as a successful experiment.
